# CI project

Project on which the CI tests Silence (`python tests/run_ci.py`; locally, with the
database of `silence.json`, `silence_ci_db`, or the `SILENCE_DB_*` variables).

It comes from [DEAL-US/Silence-CI-Project](https://github.com/DEAL-US/Silence-CI-Project)
(Silence 2), adapted to Silence 3:

- `silence.json` instead of `settings.py`, with the scripts of `sql/` in `database.scripts`:
  `run_ci.py` creates the database with `silence createdb` before the tests (and again before the
  unit tests).
- `endpoints/auto_*.json` are generated (Endpoints → Generate from the database, or
  `silence createapi`) and versioned. Regenerate them after changing the schema or the generator.
  The generated tests are not files: Silence computes them when they are asked for.
- The passwords of `populate_database.sql` are argon2 hashes (they used to be
  `pbkdf2`), still the part of the email before the `@`.
- `create_views.sql` uses `CREATE OR REPLACE VIEW`, so the scripts can be run again.

Assertions of `test/` that change on purpose:

| Test | Silence 2 | Silence 3 |
|---|---|---|
| `POST` of `departments` and `employees` (`test_departments`, `test_employees`) | 200 | 201 |
| A role that is not allowed (`test_roles`) | 401 | 403 (401 only without a session) |
| Fields of the created or edited employee (`test_employees`) | include `password` | without `password`: it is never served |
| The testing user (`utils.get_token`, `test_login`) | created with `/register` | a user of the data: there is no register |

New in Silence 3 (not in Silence 2):

- The autogenerated endpoints are all public (requiring a session is part of customizing).
  `endpoints/departments.json` and `endpoints/employees.json` customize `create`, `update` and
  `delete` with `auth_required: true`, as Silence 2 generated them, so the tests of `test/`
  that expect a 401 without a session still pass.

- `endpoints/employees.json`: `PUT /employees/$employeeId/salary` with
  `"owner": "bossId"` (only the boss of an employee changes their salary).
- `tests/employees.json`: custom unit tests (the owner rule, a CHECK, creating a user without a
  session, and the login).
- `test_login`: `POST /logout` closes the session of a token.
